# Локальная резервная копия FitPP на macOS

**Реальный экспорт не запускался.** Подготовлены только код и инструкция. Выполняйте команды экспорта ниже только после своего решения начать резервное копирование на Mac. Не запускайте их в Codex, CI или GitHub Actions.

## Что делает инструмент

- Читает проект **fitpp-crm**, базу **(default)**, документы непосредственно в коллекции **trainers**.
- Можно выбрать ровно одного тренера по Firebase Auth UID либо явно всю коллекцию.
- Получает **весь документ без маски полей**: `clients`, `attendance`, `finances`, метаданные операций и любые другие поля, включая `createTime`/`updateTime` документа.
- Запросы данных — исключительно HTTPS **GET** к `firestore.googleapis.com`. Нет операций записи, удаления, импорта, изменения правил или облачного экспорта в Cloud Storage. Перенаправления с токеном запрещены, проверка TLS включена.
- Записывает только локальные `.json` и `.sha256`, вне Git. Папка имеет права 700, файлы — 600. Существующие файлы не перезаписываются. Скрипт не печатает содержимое документов или токены.
- Не имеет телеметрии и функций загрузки копии во внешние сервисы. Папку резервных копий не включайте в iCloud, Dropbox, OneDrive, Git и другие синхронизации. Стандартное расположение — `~/FitPP-Local-Backups`, вне Desktop и Documents; известные облачные каталоги блокируются, но обнаружить произвольную настроенную синхронизацию автоматически невозможно.

Это копия полных **документов**, а не всего проекта Firebase. Подколлекции, Firebase Authentication, Security Rules, индексы и Storage сюда не входят. При наличии подколлекций потребуется отдельный инструмент. Копия сохраняет конфиденциальные данные без шифрования внутри JSON: используйте Mac с FileVault и храните файлы как личные данные, не отправляйте их в чат, GitHub или Codex.

## 1. Установить инструменты на своём Mac

Нужны Python **3.10+** и Google Cloud CLI. Дополнительных Python-пакетов не требуется.

- Python: https://www.python.org/downloads/macos/
- Google Cloud CLI: https://cloud.google.com/sdk/docs/install-sdk#mac

Проверьте в Terminal:

```sh
python3 --version
gcloud --version
```

Скачайте `backup.py` и сохраните, например, в `~/FitPP-Backup-Tool/backup.py`. Сам код можно хранить в Git, **полученные резервные копии — нельзя**.

Просмотр справки не выполняет авторизацию и не обращается к Firestore:

```sh
python3 "$HOME/FitPP-Backup-Tool/backup.py" --help
```

## 2. Авторизоваться локально как владелец

```sh
gcloud auth login
```

Завершите вход владельца проекта в открывшемся окне Google. Пароль вводится только на странице Google, если потребуется. Не создавайте и не скачивайте приватный ключ service account. Не отправляйте пароль, ключи, токены или файлы учётных данных в чат.

У владельца должны быть права IAM на чтение Firestore. OAuth-доступ через Google Cloud использует IAM, а не клиентские Firebase Security Rules; скрипт их не обходит изменением правил и ничего не развёртывает. Токен владельца сам по себе может иметь более широкие полномочия, чем скрипт: ограничение GET обеспечено кодом этого инструмента. Для отдельного read-only аккаунта администратор может заранее предоставить роль `roles/datastore.viewer`; инструмент не меняет IAM.

Скрипт сам запрашивает короткоживущий access token у локального `gcloud`, держит его только в памяти и отправляет только Google Firestore по HTTPS. Нет необходимости выполнять `gcloud auth print-access-token` вручную, копировать токен или помещать его в переменные окружения. Локальное хранилище входа обслуживает Google Cloud CLI, отдельно от кода и резервных копий.

## 3. Запустить экспорт — только когда готовы

Следующие команды — **инструкция для вашего Mac**, здесь они не выполнялись.

Вместо `owner@example.com` укажите Google-аккаунт, под которым завершён локальный вход. Это не пароль и не Firebase Auth email тренера.

Для одного тренера:

```sh
python3 "$HOME/FitPP-Backup-Tool/backup.py" \
  --account 'owner@example.com' \
  --trainer-id 'FIREBASE_AUTH_UID_ТРЕНЕРА'
```

UID возьмите локально из Firebase Console → Authentication → Users либо из имени документа `trainers/{uid}`. Если выбрали конкретный UID, копия не включает других тренеров.

Для всей коллекции `trainers`:

```sh
python3 "$HOME/FitPP-Backup-Tool/backup.py" \
  --account 'owner@example.com' \
  --all-trainers
```

Не помещайте Terminal-вывод с содержимым базы в чат. Инструмент выводит только путь готового файла и результат проверки.

Можно явно выбрать **другую локальную папку вне Git и синхронизации**:

```sh
python3 "$HOME/FitPP-Backup-Tool/backup.py" \
  --account 'owner@example.com' \
  --all-trainers \
  --output-dir "$HOME/FitPP-Local-Backups"
```

Если выбранная папка уже существовала и имеет общие права доступа, скрипт завершится без чтения документов. Для своей выделенной папки задайте:

```sh
chmod 700 "$HOME/FitPP-Local-Backups"
```

## 4. Проверка полноты и целостности

Скрипт определяет время сервера Google и читает снимок примерно **за две секунды до начала**. Точное `readTime` записано в JSON: изменения после него в копию не входят. Все страницы и обе проверки используют один и тот же момент времени.

Проверяются:

1. Все страницы ответа, отсутствие повторяющихся токенов и документов, правильный проект/путь/UID.
2. Повторный полный проход по тому же снимку — совпадение **всех полей**, а не только числа документов.
3. JSON round-trip до записи, чтение локального файла после записи, число документов и SHA-256 файла.

После успешного завершения появляются два файла:

```
~/FitPP-Local-Backups/fitpp-backup-<время>-<случайный-суффикс>.json
~/FitPP-Local-Backups/fitpp-backup-<время>-<случайный-суффикс>.sha256
```

Сохраните оба. Проверить позже **без интернета, gcloud и чтения Firebase**:

```sh
python3 "$HOME/FitPP-Backup-Tool/backup.py" \
  --verify-file "$HOME/FitPP-Local-Backups/ИМЯ_ГОТОВОЙ_КОПИИ.json"
```

SHA-256 выявляет повреждение файла, но не является цифровой подписью: не заменяйте одновременно JSON и его контрольную сумму. Проверка локального файла подтверждает его целостность, а не совпадение с текущим состоянием базы после создания копии.

При HTTP 401/403, ошибке TLS, неполной пагинации или несовпадении чтений копия не объявляется полной. Операция не переключается на незащищённое соединение. Снимок ограничен стандартным окном исторического чтения Firestore: если большой экспорт длится больше часа, сервер может его отклонить; начните новый экспорт. Нет автоматического перехода к чтению без фиксированного времени.

## 5. Формат для восстановления без потери типов

Файл имеет формат `fitpp-firestore-protojson-v1`. В `documents` сохранены полные объекты `google.firestore.v1.Document` в Firestore REST ProtoJSON, включая типизированный `fields`. Это **не** результат Firebase `.data()` и не набор упрощённых пользовательских JSON-объектов.

Сохраняются теги `integerValue`, `doubleValue`, `timestampValue`, `referenceValue`, `bytesValue`, `geoPointValue`, `arrayValue`, `mapValue`, `booleanValue`, `nullValue`, `stringValue`, а также неизвестные инструменту поля ответа. 64-битные integer остаются строками, Timestamp сохраняет наносекунды, bytes — исходный Base64, Reference — полный путь, специальные double (`NaN`/`Infinity`) — представление протокола, отрицательный ноль сохраняет знак.

Будущий инструмент восстановления должен декодировать **Firestore Value**, а не записывать `integerValue`/`mapValue` как обычные поля клиента. Восстановление не входит в этот инструмент, и оно требует отдельного подтверждения и тестового проекта. Серверные `createTime`/`updateTime` сохранены для аудита; назначить документам прежние серверные времена обычным REST-восстановлением нельзя. Правила/индексы/Auth и подколлекции этот JSON не восстанавливает.

## Проверки разработчика

Тесты используют исключительно вымышленные данные и локальные временные файлы; реальный `gcloud` и сеть в тестах не вызываются:

```sh
python3 -B -m unittest discover -s tools/firestore-backup -p 'test_*.py' -v
```

Проверены пагинация и повторное чтение, типы и точность, отрицательный ноль, права файлов, запрет Git-папок, несовпадение/повреждение копии, запрет перенаправлений, GET-only транспорт и отсутствие утечки вывода авторизации. Реальное чтение `fitpp-crm` до отдельного разрешения не выполняется.
